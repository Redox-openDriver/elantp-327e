# Безопасность

## Что делает служба на Linux
`elantpd` работает от root, но без единой привилегии ядра: в systemd у неё пустой набор возможностей,
`NoNewPrivileges`, файловая система только для чтения, своя пустая сеть и доступ только к `/dev/uinput` и
устройствам ввода (`systemd-analyze security` оценивает открытость в 1.1 из 10). Права root нужны лишь потому, что
узлы тачпада и `/dev/uinput` принадлежат root, а давать их отдельной учётной записи через правила udev значило бы
открыть создание виртуальных клавиатур кому-то ещё.

Служба читает только этот тачпад: отчёты `hidraw` с проверкой варианта (04F3:327E, дескриптор 675 байт) и узлы
`evdev`, которые она захватывает, чтобы система не получала касания дважды. Она создаёт виртуальные устройства:
копию тачпада для libinput, мышь и клавиатуру для действий жестов, перо для режима планшета. Без включённых жестов
она не захватывает ничего. Команды и программы из настроек не запускаются: действия — только щелчки и клавиши.
Настройки лежат в `/etc/elantp`, писать туда может только root.

## Клавиатура
Раздел `[typing]` в `elantp-dev drive` следит за клавиатурами, чтобы тачпад замолкал при наборе. Он смотрит только на
момент нажатия и на то, модификатор ли это; какие клавиши нажимаются, нигде не сохраняется и никуда не передаётся.
Служба `elantpd` за клавиатурой не следит: отключение при наборе в родном режиме делает libinput.

## Прошивка
Драйвер не умеет строить служебные отчёты тачпада для обновления прошивки и не посылает ему ничего, кроме
стандартных команд HID over I2C: включение, сброс и режим тачпада. Чужой вариант тачпада он не трогает вовсе.

## Как сообщить об уязвимости
Через закрытое сообщение об уязвимости на странице репозитория в GitHub (Security → Report a vulnerability), не в
открытом обсуждении.
